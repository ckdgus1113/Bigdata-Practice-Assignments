# 관찰 노트

## Task 1 · 저장할 수 없는 스트림에 답하기

- **Bloom filter**: `add`가 비트를 켜기만 하고 끄는 코드가 없어서, 넣은 원소의 k개 비트는 항상 켜져 있으므로 거짓 음성이 구조적으로 없습니다. 거짓 양성률은 예측 0.860%(`(1 - e^{-kn/m})^k`), 측정 0.790%이고, 차이 0.07%p는 20,000번 조회의 표준오차(약 0.065%p) 안입니다.
- **Flajolet-Martin**: 지수 R을 평균 낸 뒤 `2^평균`을 1.26으로 나누는 규칙을 썼고, 30번 시험에서 0.71~1.39배로 2배 안에 안정적으로 들어온 유일한 규칙이었습니다. `2^R` 단순 평균은 최대 1,095배, 중앙값은 한 번 2.12배, 그룹 평균 후 중앙값은 1.4~6.5배까지 벗어났습니다.
- **Reservoir**: `enumerate(stream, start=1)`의 `n`은 지금까지 지나간 개수일 뿐 전체 길이를 쓰지 않고, `randrange(n) < k`일 때만 교체하므로 n번째 원소가 확률 k/n으로 들어옵니다.

## Task 2 · 한계 찾기

- **불쾌해진 크기**: n=25,000,000으로 잡았습니다(제가 정한 기준이고 컴퓨터가 못 버틴 지점은 아닙니다). exact가 85초, 745 MB였고 먼저 모자란 것은 시간입니다(RAM 15.4 GB의 5%라 메모리 벽은 보지 못했습니다).
- **증가율**: n이 250배일 때 exact 메모리는 약 190배 늘었고(로그-로그 기울기 약 0.95, 원소당 약 81~107바이트), FM은 4.0~5.4 KB에서 n과 무관하게 평평했습니다(기울기 약 0). FM 비율은 0.94~1.58배였습니다.
- **2배면 충분한가**: 고유 방문자 수로 서버 용량을 가늠하는 용도에는 충분하고, 광고 노출 요금 청구나 몇 % 단위 추세에는 부족합니다(비율이 0.94~1.58배로 흔들려서 10% 변화는 잡음에 묻힙니다).

## Task 3 · 같은 메모리, 더 적은 실수

- **바꾼 것**: 해시 개수 k를 1에서 7로 바꿨습니다. `(1 - e^{-kn/m})^k`를 k로 미분해 0으로 놓으면 `k = (m/n)·ln2`이고, m/n = 10이므로 6.93이며 정수 6과 7 중 값이 낮은 7(0.8194%, 6은 0.8436%)을 골랐습니다.
- **하한(R6)**: m/n = 10의 이론 최소는 `(1/2)^{10 ln2}` = 0.819%이고 측정은 0.831%(9.511%에서 91.3% 감소, 거짓 음성 0)로, 차이 0.012%p는 표본오차 안이라 하한에 도달했습니다.
- **n을 모를 때**: 너무 낮게 잡으면 비트가 가득 차서 거짓 양성이 치솟고(거짓 음성은 0이지만 필터가 쓸모없어짐), 너무 높게 잡으면 메모리와 k만 낭비합니다. 채워진 비율을 감시하다가 한계에 가까워지면 더 큰 필터를 이어 붙이겠습니다(구현·시험은 하지 않았습니다).
